# 性能与兼容性检查（P6）

检查方式：`npm run dev` 运行后执行 `npm run perf`（`tools/perf.mjs`）。脚本用 Playwright 驱动本机 Google Chrome 和 WebKit（Safari 内核），分辨率 1440 × 900、2 倍像素密度，对三座城各做一遍：加载关卡 → 地图平移时采样 180 帧 → 进入一个较重的地块 → 地块里采样 180 帧，并收集控制台错误。

## 模型下载优化（2026-10-18）

v2 精模上线后，一个较重的地块要下载 10 个左右精模（62–67 万面，单个最大 9.4 MB）。现在做了两件事：

1. **简模先到、精模按需**：地块只先下载远景简模（v1），精模等到某个实例在屏幕上宽于 340 CSS px、`chooseLods()` 真要切过去时才下载，下载期间继续显示简模。远近两级都按 `data/models.json` 里精模的 `bounds` 归一化，精模到了以后位置、大小完全不变（实测两级的摆放矩阵逐项相同）。默认相机距离下主体约 190 px，所以进入地块时一个精模都不用下；拉到最近（750 m）一般只下主体那一个。
2. **glb 量化**：`tools/export_assets.py` 导出时把位置量化成 int16（按网格统一缩放，最大误差约 0.9 mm）、法线量化成 int8（误差 < 0.4°），走标准 KHR_mesh_quantization，反量化变换挂在节点上。加载器解码回浮点后再上传，着色器里程序化纹理用的「模型坐标（米）」不变。没有去掉法线：v2 精模里柱子、屋脊等平滑部分有 1–3% 的顶点，用面法线重算会偏差 6–16°。描边用的平滑法线改用整数哈希表分组，不再用字符串键。

## 本轮修掉的问题

| 问题 | 浏览器 | 处理 |
|---|---|---|
| 进入地块时偶发 `texImage2D: bad image data`，随后 `generateMipmap` 报错，云海贴图缺失 | WebKit | 同一张云图正被 DOM 云雾动画使用时，用 `<img>` 上传贴图会失败。贴图加载改为 `fetch → createImageBitmap`（与 DOM 无关、解码时预乘 alpha），不支持时再退回 `<img>` |
| 每个页面一次 favicon 404 | 全部 | 加内嵌 SVG 图标 |

## 加上的保护

- **画质自动降档**：关卡页连续约 2 秒平均帧间隔超过 25 ms，就把画布像素密度从 2 降到 1（模拟慢机器测试过：画布宽 2560 → 1280）。
- **不支持 WebGL2 时**：页面显示中文说明，提示换浏览器或开启硬件加速。
- **音频**：浏览器要求先有用户操作，第一次点击或按键后才创建 AudioContext；右下角可静音，设置会记住。

## 体积

构建产物 `dist/` 共约 13 MB（v2 精模之前的数字）：模型 4.5 MB（32 个 glb）、底图 2.8 MB、概念图 4.6 MB。概念图只在某个资产缺模型时才按需加载，目前三城都不会用到。部署时建议服务器对 `.glb` 开启 gzip 或 brotli（纯色无贴图的 glb 压缩率很高）。v2 精模和量化后的模型体积见上文「模型下载优化」。

## 未覆盖

- **Firefox**：本机没有 Firefox，也没有对应的 Playwright 浏览器，未测试。
- **移动端**：触屏可以单指拖动、点按，但地图不支持双指缩放；浮窗布局也没有针对窄屏调整。
- **低端 / 集成显卡**：只在 M4 上实测过；降档逻辑用模拟慢帧验证过，没有真机数据。
- **底图超分**：见 [搭建计划](搭建计划.md) 的进度记录。管线已经支持高分辨率底图：把超分后的原图放到 `assets/raw/maps/upscaled/{xiangyang|jingzhou|baoding|overview}.png`，运行 `python3 tools/export_assets.py`，标定坐标会按 `calibration.imageSize` 自动换算，不用重新标定。
