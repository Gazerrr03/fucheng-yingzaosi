# 建模任务书 v1（参考图 → Blender → glb）

> **2026-10-17 更新**：用户把精度标准提高到「可以第一人称近看、至少相当于《文明 6》」。现有 32 个模型的体检结果与升级方案见 [模型体检报告.md](模型体检报告.md)；本任务书的面数预算和「纯色无贴图」约定将随构件库 v2 一起修订。

> 本任务书不要求一次把模型做完。每个资产分三个阶段：
> **A. 参考板**：用 image 工具生成建模用的正投影参考图；
> **B. Blender 建模**：设立 goal，由 computer use 操作本机 Blender 完成；
> **C. 导出验收**：导出 glb，用现有工具检查并在游戏里看效果。
>
> 范围：先做襄阳用到的 **23 个资产**（第 7 节任务卡）。荆州、保定的资产等襄阳跑通后另出补充任务卡。
> 相关文档：[3D建模指南](3D建模指南.md)（外观依据、资产总表、接入流程）· [生图任务书](生图任务书.md)（风格基调）

---


> **构件库 v2 与远近模型（2026-10-18）**：精模用 `tools/blender/kit2.py` 建，色板新增 `teal`、`qing`、`gold`、`ink`（明代彩画的青绿与点金）。每个资产升级到 v2 时，旧的 v1 脚本改名为 `build_{ID}_far.py`，产出 `{ID}_far.glb` 作为远景简模，并在 `data/models.json` 里填 `far`。纹理由游戏的着色器按材质名程序化生成，建模时**仍然只用纯色材质**，材质名必须来自色板。近看验收用 `tools/blender/closeups.py`，几何体检用 `tools/blender/audit_models.py`。截至 2026-10-18，32 个资产已全部升级到 v2（见体检报告第 7 节）。远景简模按精模的包围盒归一化，所以简模不必和精模外轮廓完全一致。精模面数参考：单体建筑 4～10 万，大型院落、多层楼阁不超过 18 万。

## 1. 总流程

```
[A 参考板]  概念图 + 风格主图 + 任务卡尺寸
            └─ image 工具 ─► assets/model_refs/{ID}/sheet.png（正投影四视图）
                                                │
[B 建模]    设立 goal（第 5 节模板）            ▼
            computer use 打开 Blender 5.2 ─► 运行 tools/blender/build_{ID}.py 生成几何
            ─► 截四视图与参考板对比 ─► 改脚本参数，必要时在界面里手动微调 ─► 循环
                                                │
[C 验收]    导出 assets/models/{ID}.glb ─► node tools/check_models.mjs {ID}
            ─► python3 tools/export_assets.py --models-only ─► 进游戏对应地块查看
```

**为什么几何用脚本生成、界面只做检查：** computer use 逐个点击建模很慢，也很难精确。中国古建筑由少数几种构件反复组合而成（城台、墙、柱网、屋顶、台基），这些用参数化脚本生成既快又一致；Blender 界面用来看效果、截图对比，以及做少量手工修整。

## 2. 统一规范

### 2.1 坐标、尺寸、朝向

| 项 | 要求 |
|---|---|
| 单位 | 1 Blender 单位 = 1 米，按第 7 节给的**真实尺寸**建（游戏里会再缩放到显示宽度，但真实尺寸能保证比例正确） |
| 原点 | 底面中心，落在 Z = 0 |
| 朝向 | **正面朝 Blender 的 -Y 方向**，也就是按小键盘 `1`（前视图）看到的就是正面。导出为 glTF 后对应 +Z，在游戏里朝南 |
| 变换 | 导出前对所有物体应用缩放和旋转（`Ctrl+A → All Transforms`），或在导出时勾选应用 |
| 法线 | 全部朝外（`Mesh → Normals → Recalculate Outside`）；屋顶、墙体这类硬边用 `Shade Auto Smooth`（30°） |

### 2.2 面数预算

| 类别 | 三角面 |
|---|---|
| 点缀（树、船、单体民居） | ≤ 6,000 |
| 通用构件（墙段、城门、院落、桥） | ≤ 20,000 |
| 地点主体（X 系列） | ≤ 40,000 |

脚本生成的模型通常远低于这个上限；预算主要用来防止手工加细节加过头。

### 2.3 材质与色板

**不用贴图，只用纯色材质。** 游戏的卡通着色会统一明暗，纯色块反而最贴近底图的手绘平涂风格，也免去展 UV。每个模型只从下面的色板里选材质，**材质名必须和色板名一致**，方便以后统一调色。

色板从 37 张概念图中统计得到，数值为 sRGB：

| 材质名 | 颜色 | 用于 |
|---|---|---|
| `brick` | `#AA997F` | 城砖墙面、城台 |
| `brick_light` | `#C3AE90` | 垛口、墙顶、压檐石 |
| `brick_dark` | `#6A6254` | 门洞内壁、墙基 |
| `tile` | `#535556` | 青灰瓦屋面 |
| `ridge` | `#3F4142` | 屋脊、瓦当线（比瓦稍深） |
| `vermilion` | `#8A3E2C` | 柱、门窗、栏杆（朱红） |
| `plaster` | `#E6D5BD` | 粉墙、民居墙面 |
| `marble` | `#E6DAC6` | 汉白玉台基、栏杆、牌坊 |
| `stone` | `#AFA189` | 石桥、台阶、码头 |
| `earth` | `#E7C392` | 夯土坛台、土路 |
| `wood` | `#8A6B50` | 船、木构外露部分 |
| `trunk` | `#755E45` | 树干 |
| `leaf` | `#737C60` | 杂木树冠 |
| `pine` | `#596351` | 松针 |
| `willow` | `#798169` | 柳叶 |
| `ginkgo` | `#CDB85E` | 银杏（秋色） |
| `jade` | `#65715C` | 绿影壁壁心 |
| `void` | `#2B2520` | 门洞深处、窗格暗面（模拟凹陷阴影） |

> 门洞、窗洞不必真的挖穿：贴一块 `void` 材质的内凹面，在卡通着色下就有足够的深度感，面数也省。只有城门洞这种能看穿的，才用布尔挖空。

### 2.4 导出参数（Blender 5.2 glTF 导出器）

`File → Export → glTF 2.0`，或在脚本里调用 `bpy.ops.export_scene.gltf`：

| 选项 | 值 |
|---|---|
| Format | glTF Binary (`.glb`) |
| Include | 只导出可见物体；不要相机和灯光 |
| Transform | +Y Up ✔ |
| Data → Mesh | Apply Modifiers ✔，Normals ✔，UVs 可关 |
| Data → Material | Export |
| Compression | **关闭**（游戏的加载器不支持 Draco） |
| Animation | 关闭 |

脚本写法（5.x 的参数名如有变化，以当前版本 `bpy.ops.export_scene.gltf` 的签名为准）：

```python
bpy.ops.export_scene.gltf(
    filepath=out_path, export_format='GLB', export_yup=True,
    export_apply=True, export_materials='EXPORT', export_cameras=False,
    export_lights=False, export_animations=False,
    export_draco_mesh_compression_enable=False, use_visible=True,
)
```

## 4. 阶段 B 的前置：构件库 `tools/blender/kit.py`

**第一个 Blender 任务就是写好并验证构件库**（任务卡 M0），之后每个资产的脚本只做组合。接口约定如下，实现可以按需要调整，但函数名和参数含义要保持，各资产脚本都依赖它们。

| 函数 | 生成什么 | 主要参数 |
|---|---|---|
| `setup_scene()` | 清空场景，设米制单位，创建色板材质（第 2.3 节） | — |
| `mat(name)` | 取色板材质 | 色板名 |
| `wall(length, height, top_w, bottom_w, crenel=True)` | 带收分的城墙段，外侧垛口，内侧女墙 | 垛口宽 1.2、高 1.6、间距 1.0 |
| `platform(w, d, h, batter=0.06, arch=None)` | 砖砌城台 / 台基，四面收分；`arch=(宽, 高)` 时沿 Y 向打通拱形门洞 | 城门洞用布尔挖空 |
| `stair(w, run, rise)` | 台阶 | — |
| `column_grid(bays_x, bay_w, bays_y, bay_d, col_h, r)` | 柱网（朱红圆柱 + 柱础） | 开间数、进深间数 |
| `hall(bays_x, bay_w, bays_y, bay_d, col_h, roof, stories=1, base_h=0.6, gallery=False)` | 一座木构殿 / 楼：台基、柱网、墙门窗、屋顶；`stories=2` 时为楼阁，上层略收 | `roof` 取下面的屋顶类型 |
| `roof(kind, w, d, h, overhang, curve, double=False)` | 屋顶：`'xieshan'` 歇山、`'wudian'` 庑殿、`'yingshan'` 硬山、`'juanpeng'` 卷棚；`double=True` 为重檐；`curve` 控制檐角起翘 | 坡面 `tile`，屋脊 `ridge` |
| `ma_tou_wall(length, steps)` | 马头墙（南方民居山墙） | — |
| `enclosure(w, d, h, gates)` | 院墙、壝墙、瓮城墙；`gates` 指定开门的边和位置 | 墙顶带瓦压顶 |
| `paifang(bays, w, h, stone=True)` | 牌坊 / 棂星门 | 石或木 |
| `arch_bridge(length, width, spans, rise)` | 石拱桥，带栏板 | — |
| `tree(kind, height)` | 低面数树：`'broadleaf'`、`'pine'`、`'willow'`、`'ginkgo'` | 树冠用少量变形的二十面体 |
| `boat(length, covered=False)` | 木船 / 篷船 | — |
| `render_review(id)` | 用 Workbench 引擎从前、右、顶、45° 轴测四个方向，各渲染一张 1024² 图，存到 `assets/model_refs/{id}/review_*.png` | 平光、白底、轮廓线开 |
| `export(id)` | 应用变换，按第 2.4 节导出到 `assets/models/{id}.glb`，同时保存 `.blend` | — |

**屋顶是最难也最关键的部分**，决定了建筑是否像明代建筑。最低要求：
- 坡面为直坡加檐口微翘；
- 歇山顶要有上半段的山花（三角形山面）和下半段的四面坡；
- 屋檐挑出柱网至少 1.5 米；
- 正脊两端略起翘（简化的鸱吻）。

斗栱不做实体，用檐下一圈 `vermilion` 和 `ridge` 相间的带状面暗示即可。

## 5. 阶段 B 的 goal 模板

每次开一个 computer use 会话做一个资产（M0 构件库单独一次）。把下面模板里的 `{…}` 换成任务卡内容后作为 goal：

```
目标：用本机 Blender 5.2（/Applications/Blender.app）完成 {ID} {名称} 的建模，
导出 assets/models/{ID}.glb。

输入：
- 任务卡：docs/建模任务书.md 第 7 节 {ID}（尺寸、结构拆解、外观依据以任务卡为准）
- 参考板：assets/model_refs/{ID}/sheet.png；概念图：public/assets/concepts/{ID}_main.webp、{ID}_side.webp
- 构件库：tools/blender/kit.py（不要修改已有函数的行为；需要新能力时新增函数，并在报告里说明）

做法：
1. 写 tools/blender/build_{ID}.py：setup_scene() → 组合构件 → render_review('{ID}') → export('{ID}')。
2. 在 Blender 的 Scripting 工作区打开该脚本并运行；切到 Layout，从前、右、顶、轴测四个视角截图。
3. 把截图、assets/model_refs/{ID}/review_*.png 与参考板逐项对比：轮廓、层数、开间数、高宽比、屋顶形式、门洞位置。
   不一致就改脚本参数后重跑；脚本难以表达的细节，可以在界面里手动修整后另存 .blend。
4. 运行 node tools/check_models.mjs {ID}，必须显示 ✓。

完成标准（全部满足才算完成）：
- [ ] check_models 通过，面数不超过任务卡预算
- [ ] 四视图与参考板在轮廓、层数、开间数、屋顶形式上一致；尺寸误差 ≤ 10%
- [ ] 原点在底面中心、Z=0 落地；正面朝 -Y；材质名全部来自色板
- [ ] 已保存 tools/blender/build_{ID}.py、assets/blender/{ID}.blend、assets/model_refs/{ID}/review_*.png
- [ ] 运行 python3 tools/export_assets.py --models-only 后，进入游戏地块「{地块}」，
      控制台 __tile.modelReport 中 {ID} 的 source 为 glb，截图确认朝向和大小正常

不要做：不改其他资产的文件；不改游戏代码；不提交 git。
完成后报告：面数、四视图路径、与参考板不一致的地方及原因、对构件库的新增或改动。
```

**computer use 操作 Blender 的注意事项（M0 实测）：**
- Blender 窗口必须和当前桌面在同一个 Space 里，才能点进去。如果你当前用的是全屏应用的 Space，后台点击不会生效，窗口也无法被移过来。最省事的做法是用命令行启动 Blender 并在启动时直接运行脚本，再用 computer use 看界面、在 Python 控制台里输入命令：
  ```bash
  /Applications/Blender.app/Contents/MacOS/Blender --factory-startup --python tools/blender/build_kit_demo.py
  ```
- Blender 的界面是自绘的，没有无障碍元素，只能按坐标点击。窗口大小一变，坐标就跟着变，每次点击前都要先截图。
- 在 Scripting 工作区的 Python 控制台里，可以直接用命令把脚本载入文本编辑器，然后点 ▶ 运行：
  `t = bpy.data.texts.load('<脚本路径>'); [a.spaces.active for a in C.screen.areas if a.type == 'TEXT_EDITOR'][0].text = t`
- 进游戏检查时，在浏览器控制台输入 `__enter('<site id>')` 可以直接进入该地块，再看 `__tile.modelReport`。

只想批量重新导出（不看界面）时，也可以无界面运行：

```bash
/Applications/Blender.app/Contents/MacOS/Blender -b -P tools/blender/build_X01.py
```

## 6. 阶段 A：参考板生图

### 6.1 通用要求

- **输入参考**：该资产的 `public/assets/concepts/{ID}_main.webp`、`{ID}_side.webp`，加上 `assets/raw/style/style_master.png`；有实拍照片的，再加上任务卡里列的照片。
- **尺寸**：2048 × 2048，一张图里排 2×2 四个视图。
- **布局**：左上为正立面（从南看），右上为侧立面（从东看），左下为顶视平面，右下为 45° 轴测。
- **画法**：建筑设计正投影图的风格。白底，线稿加平涂色块（用第 2.3 节色板），无透视、无投影、无环境、无人物、无文字。
- **一致性**：四个视图必须是同一座建筑，开间数、层数、屋顶形式完全一致。生成后先自查这一点，不一致就重生成。
- **尺寸以任务卡为准**：生图的比例只作形态参考，不精确；与任务卡数字冲突时，以任务卡为准。

### 6.2 提示词模板

**中文**
> 建筑正投影建模参考板，2×2 四视图排版：左上正立面，右上侧立面，左下顶视平面，右下 45° 轴测。同一座建筑：{任务卡「参考板要点」}。白色背景，线稿加平涂色块，配色为赭石城砖、青灰瓦、朱红柱、米白粉墙；无透视、无投影、无文字、无人物、无地面环境。明代建筑形制，比例严谨，适合作为 3D 建模参考。

**English**
> orthographic architectural model sheet, 2×2 layout: front elevation top-left, side elevation top-right, top plan bottom-left, 45° axonometric bottom-right. The same building in all four views: {key points in English}. White background, clean line drawing with flat color fills, palette of ochre brick, slate-grey roof tiles, vermilion columns, off-white plaster; no perspective, no shadows, no text, no people, no ground scenery. Ming-dynasty Chinese architecture, accurate proportions, suitable as a 3D modeling reference.

**负面提示词**
> perspective distortion, dramatic lighting, shadows, landscape, people, text, labels, dimensions, watermark, inconsistent views, different buildings in each view, photorealistic

### 6.3 细节图（只给地点主体做，可选）

X01、X02、X04、X05 另出 1～2 张 1024² 的细节图，文件名 `detail_*.png`。内容是屋脊和檐角、门洞拱券、绿影壁壁心与边框的特写，同样用正投影或微俯视，白底。

## 7. 任务卡（襄阳 23 个资产 + 构件库）

> **尺寸**按资料换算（明营造尺约 0.32 m）。资料里没有的，按明代地方建筑常见尺度估算，标「估」。
> **用途**：「主体」= 某个地点的中心建筑；「点缀」= 地块邻格上的陪衬。
> **地块**：验收时进游戏看的地点（括号里是 site id）。

### M0 · 构件库

- **产出**：`tools/blender/kit.py`，以及一个示范脚本 `tools/blender/build_kit_demo.py`。它把第 4 节的每个函数各调用一次排成一排，渲染四视图并存到 `assets/model_refs/_kit/`。
- **完成标准**：
  - 每个函数都能运行；
  - 歇山、庑殿、硬山三种屋顶在轴测图上形态可辨；
  - 拱形门洞能看穿；
  - 导出的 `_kit_demo.glb` 能通过 check_models（ID 不在清单里会提示，属正常）。
- **面数**：不限（示范用）。

### 批次 1：打通流程（先做这 4 个）

#### K01 · 城墙直段　点缀 / 主体（西城墙 chengqiang）
- **外观依据**：府城资料记城墙「高二丈五尺，上阔一丈五尺，脚阔三丈」；青砖包砌，外侧垛口，内侧女墙。
- **尺寸**：长 40，高 8，顶宽 4.8，底宽 9.6（外侧收分）；垛口宽 1.2、高 1.6、间距 1.0；女墙高 1.0。
- **结构**：`wall()` 一段。墙顶用 `brick_light`，墙基一圈 `brick_dark`。
- **参考**：概念图 K01；实拍 `襄阳府资料/图片/实拍/临汉门城楼城墙.png`（看墙面与垛口比例）。
- **参考板要点**：一段笔直的明代砖砌城墙，下宽上窄，顶部外侧一排方形垛口，内侧矮女墙。
- **面数**：≤ 4,000。

**城角类构件（批次 2 加入）：** 夫人城（X03）、仲宣楼（X04）这类 L 形转角构件不能自动定向，需要在关卡数据里给地点填 `rotY`（度）。在标定工具「地点」页的「主体朝向」里填写；填了就优先于自动朝向。模型约定：X03 的两段墙沿 +X 与 +Y（Blender），墩台向 -X-Y 外凸；X04 的两段墙沿 -X 与 +Y，城台在转角。

**游戏内摆放规则（批次 1 加入）：** 城墙格上的墙段，以及城门、城墙类地点的主体，会自动顺着相邻城墙格的连线摆放，正面（带垛口的外侧）背向城内。建模时只要保证城墙类资产的长轴沿 X、外侧朝 -Y（Blender 前视图）即可。

**已知限制：** 游戏的描边沿法线向外扩出一层背面来画。硬边模型的法线在棱角处是分开的，描边在转角可能出现细小裂缝。如果验收时比较明显，由程序侧改为按平滑法线外扩来修正，建模侧不用处理。
